# 所有と契約終了（OWNERSHIP_AND_EXIT）

商談用・非公開。**最終的な契約書ではなく、商談で話す論点の整理。** 権利・利用許諾・個人情報の扱いは、正式な契約と法務確認で決める。

## 原則

**メディアは先方の資産。メディアを動かす汎用エンジンは匠Technologies の資産。**
ただし「エンジンは匠の所有」を理由に、契約終了と同時に記事・条件整理チェック・メディアが動かなくなる設計にはしない。

## 先方に残る想定のもの

| 資産 | 渡し方の例 | 備考 |
| --- | --- | --- |
| メディアのブランド・ドメイン | 先方所有の新規ドメインを想定（名義・費用負担は契約時に確定） | ドメイン取得・DNS 変更は今回しない |
| 専用の記事・ニュース解説・職種比較・読む順番ガイド | `content/*.md`（frontmatter つき Markdown）、`export/pages/*.md` | 出典・情報確認日などのメタデータも含む |
| 専用のデザイン・LP・SNS 制作物 | カルーセルPNG・原稿・台本・絵コンテ・専用の制作データ | 第三者の素材・フォント・音源は各ライセンスに従う |
| メディア固有の設定 | 相談先・計測パラメータ・表記（`src/config/partner.ts` の該当部分） | |
| 計測・成果のデータ（適法な範囲） | イベントの集計、提携先から返された成果データの集計 | 個人データを「先方の所有資産」とは表現しない。扱いは個人情報保護の枠組みで決める |
| 運用資料・引き継ぎ資料 | この docs/sales 一式、運用手順、URL 一覧 | |
| 静的に動く書き出し | `npm run export:static` の `export/site/`（JS・CSS・フォント込み） | 記事・条件整理・安全な相談案内を含む。サーバーの機能（記事検索の絞り込みなど）は含まれない |

## 匠Technologies に残るもの

IKORABU（運用基盤）、Research / Writer / Reviewer / TTP Engine、汎用 CMS・汎用コード・汎用の条件整理ロジック、計測 Engine、自動化、再利用できる運用手法。
他社向けの別メディアや共通技術の提供は禁止しない設計。ただし当該メディアの商業的な相談送客先は、契約期間中は先方専属とする構想。

## 組み込んだ汎用部品の利用権（提案できる範囲）

- 当該メディアを継続運営・保守・移管するために必要な範囲で、組み込んだ表示部分（画面のコード・条件整理チェックの表示とルール）の利用権を提案できる
- 譲渡しないもの: IKORABU 全体、共通 OS、汎用 Engine、他社への再販売権
- 第三者のライブラリ・フォント・素材は、それぞれのライセンスに従う（全権利を譲渡するとは書かない）

## 契約終了時の流れ（案）

1. 終了の30日前（目安）に、引き渡し範囲と日付を確認
2. 書き出し: 記事・メタデータ（Markdown）、URL 一覧（sitemap）、静的サイト、計測データの集計、SNS 制作物
3. ホスティング: 先方のサーバー・CMS へ移すか、静的サイトとして置くか（維持費は先方負担が前提、要相談）
4. 更新の方法: 終了後は先方で Markdown を編集してビルドする、または既存 CMS に移す
5. アクセス権の整理: 匠側の管理画面・計測・自動化の権限を外す（個人データを匠側に残さない）

## 確認が必要な論点

- 記事の著作権の帰属と、匠側が「制作実績」として紹介できる範囲
- 契約終了後の利用権の期間・範囲・対価の有無
- ホスティング・ドメインの名義と費用負担
- 計測データ・成果データの保管期間と削除
- 第三者素材（写真・音源・フォント）の扱い

## 引き渡しの受入確認

静的サイトはHTTPで配信し、Home→代表記事→Check→結果のコピー→相談案内まで確認する。`export/pages/PAGES.md` にURLと元ソースがあり、`index.md` はHome本文。汎用部品の利用権・第三者ライセンス・公開担当・維持費は契約時に確定する。SNSは画像だけでなく原稿と専用制作データを同梱し、リール台本を完成動画とは扱わない。
