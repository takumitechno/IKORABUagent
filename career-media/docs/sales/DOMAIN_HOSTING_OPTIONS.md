# ドメイン・ホスティングの選択肢（商談で確認）

商談用・非公開。**今回はドメインの取得・DNS の変更・デプロイをしていない。** 既存サイトがあるため、新しいドメインありきにしない。

| 案 | 例 | 良いところ | 確認すること |
| --- | --- | --- | --- |
| A. 既存ドメイン内のメディア領域（第一候補） | `既存ドメイン/media/` など | ブランド・検索の評価・資産がつながる。先方の資産として残りやすい | 既存 CMS で置けるか、サーバー・権限、社内の更新フロー、既存ページとの役割分担 |
| B. 先方所有のサブドメイン | `media.既存ドメイン` | 既存サイトと分けて運用しやすい。DNS の設定だけで始められる | DNS の権限、検索の評価が分かれやすい点の理解 |
| C. 先方所有の独立ドメイン | 新しいドメイン | メディアのブランドを独立させられる | 取得・更新費用、ゼロからの検索評価、既存サイトとの関係 |

## 技術面の前提（どの案でも）

- 今のメディアは Next.js。サーバーで動かす形（記事検索などが動く）と、静的に書き出す形（`export/site/`）のどちらでも置ける
- 既存 CMS に移す場合は、記事を Markdown（frontmatter つき）で渡せる
- 正式公開時は `partner.brandUsageApproved` と `SITE_INDEXABLE` を、人の判断で切り替える（今回は切り替えない）

## 決める順番

1. 既存サイトの CMS・検索の状態・権限・社内の運用を確認
2. A が難しければ B、ブランドを分けたい理由があれば C
3. 名義・費用負担・終了時の扱いを [OWNERSHIP_AND_EXIT.md](OWNERSHIP_AND_EXIT.md) と合わせて決める
