# ART_DIRECTION — 画像の方針

「はじめて転職ガイド」で使う画像（イラスト・ビジュアル）の方針。OpenAI の画像生成 API で作るときも、手で描くときも同じ。
生成の手順は [image-briefs/README.md](image-briefs/README.md)。

## 1. 画像は主役ではない

このメディアの主役は、読みやすい文章とUI、情報の確かさ、20代ではじめて転職する人へのやさしい体験。画像はページのトーンを少し助けるだけ。

- **まず画像なしで成り立たせる。** 見出し・余白・タイポグラフィ・既存の SVG モチーフ（`src/lib/illustrations/motifs.ts`）で足りるなら画像は作らない
- 画像を増やすこと自体を目的にしない。「なんとなく寂しいから」で入れない
- **文字は画像に入れない。** 見出し・数字・説明は HTML に置く（検索・読み上げ・翻訳・修正のため）。SNS の表紙も、文字は投稿時に重ねる
- 画像がなくても意味が通るようにする（`GeneratedImage` は画像がないとき今のイラストを出す）
- 生成に失敗しても、今のイラストのままで商談用の完成度は保てる。無理に入れない

## 2. トーン

| こうしたい | 避けたい |
| --- | --- |
| やさしい・清潔感・余白が多い | 不安をあおる暗さ、深刻すぎる表情 |
| メディアとして自然（読みもの） | 企業 LP・求人広告っぽい押しの強さ |
| Instagram の投稿と並べても違和感がない | 量産型 AI イラスト、ストックフォト風のわざとらしい笑顔 |
| 落ち着いた、少し温かい | キラキラ・グリッター・ネオン、過剰な 3D、青すぎる SaaS 感 |
| 日常の延長（仕事・暮らし） | スーツと握手だらけの「ビジネスビジネス」した絵 |

## 3. 推奨スタイル

- やわらかいフラットイラスト。単純な形、角の丸い図形、線は細いか無し
- 構図はシンプルに。主題は1つ、要素は3〜5個まで。余白を広く取る
- 抽象的な背景・補助図形（円・道・矢印・書類・吹き出し）でテーマを示す
- 人物を入れるときは、顔の細部を描き込みすぎない一般的な人物。性別・年齢・属性を固定しない（複数人なら多様に）
- 色はサイトと同じ（`src/app/globals.css`）

| 役割 | 色 |
| --- | --- |
| メイン | ティール `#0f7b6c`、ミント `#e3f3ec` |
| 地 | あたたかいオフホワイト `#faf8f4` |
| 細部 | ネイビー `#142b3e`（少しだけ） |
| アクセント | オレンジ `#f28c28`、サンド `#fbf0e1`（少しだけ） |

この方針は `scripts/images/lib.ts` の `HOUSE_STYLE` として、すべての生成 prompt の末尾に自動で付く。

## 3.5 写真・画像がないときの見た目

トップと記事一覧は、画像なしで転職サイトらしく見えるように作っている。

- ヒーロー: 濃いティールの面＋検索ボックス＋人物のイラスト（`public/images/illustrations/hero-people.svg`。このリポジトリで手で描いた SVG。黒髪の20代の男女、ビジネスカジュアル）。デスクトップでは「ゆずれない条件」「職種を比べる」の小さなカード（HTML）を重ねる。`hero-home` を採用すると、イラストの代わりに写真が出る
- 記事のサムネイル: カテゴリの色のグラデーションに、記事の問い（frontmatter の `eyecatch`）を太い白い文字で置き、最後の行を黄色にする文字サムネイル。右下にカテゴリのアイコンを白い丸で置く（`src/components/Eyecatch.tsx`）。記事ページの上部にも大きく出す。一覧の行では文字なしのアイコンのタイル
- 入口・ケース・ロードマップ: 色の四角＋アイコン、番号、色帯の見出し
- `npm run illustrations` の Open Peeps 場面イラスト（CC0、`public/images/illustrations/`）は素材として残しているが、今のページでは使っていない

人物の写真を使うときは、日本人のモデルが写った、商用利用できる素材（ライセンスを確認して記録する）を `hero-home` の位置に入れる。相談員・利用者・体験談に見える使い方はしない。

## 4. 使わないもの（禁止）

- 実在の企業・サービスのロゴや公式ビジュアルの模倣（MakeCareer のロゴも、許諾なしに作らない・使わない）
- 著名なキャラクター・著名人・実在の人物に似せた絵
- 個人の顔写真風の画像を何枚も並べること（体験談や実在の相談者に見えるため）
- 長い文章や数字を入れたバナー（HTML の代わりにしない）
- 指や手の形が崩れたもの、目が不自然なもの（生成画像でよく起きる。見つけたら作り直す）

`scripts/images/lib.ts` の `BLOCKED_TERMS` に当たる言葉が brief にあると、生成ツールは止まる。

## 5. どこに使うか（優先順）

1. トップのヒーロー（`hero-home`）
2. 商談用ページ・SNS 投稿案の表紙（`sns-theme-*-cover`、`/sales/sns/*`）
3. セクションの補助イラスト（条件整理チェック `check-support` など）
4. 記事の挿絵は原則使わない。図解（```figure）と表で足りない場合だけ、1記事1枚まで

## 6. 実装のルール

- 置き場: `public/images/generated/<種類>/<slug>.webp`、記録: `content/images/meta/<slug>.json`
- 表示は `src/components/GeneratedImage.tsx` を通す（縦横を記録から渡し、レイアウトのずれを防ぐ。alt は記録から）
- サイトに出るのは状態が `selected` の画像だけ。生成直後は `draft`
- 飾りの画像は `decorative: true`（alt を空にして読み上げない）。意味のある画像には具体的な alt を書く
- 形式は WebP（圧縮 85）を基本にする。透過が必要なときは `background: transparent` と WebP / PNG
- 生成は1回1枚（`n: 1`）、品質は既定 `medium`。気に入らないときは何枚も回さず、brief を直してから作り直す

## 7. 採用の判断（チェックリスト）

画像を `selected` にする前に、スマホ（幅390px）とデスクトップで実際のページに置いて確かめる。

- [ ] 画像を外しても、ページの意味が通るか
- [ ] 文字・ロゴ・透かしが入っていないか
- [ ] 手・顔・物の形が崩れていないか
- [ ] 色がサイトのパレットから浮いていないか（青や紫に寄りすぎていないか）
- [ ] 周りの見出しより目立ちすぎていないか
- [ ] 特定の性別・年齢・属性だけを描いていないか
- [ ] 不安をあおる表情・場面になっていないか
- [ ] Instagram の投稿案と並べたときにトーンがそろうか

1つでも外れたら `rejected` にして brief を直す。直し方は [image-briefs/README.md](image-briefs/README.md) の「作り直すとき」。
