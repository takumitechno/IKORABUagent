### MEGURI

- 新規アカウント追加は個別開発ではなく設定駆動にする。
- 想定フローは `契約 → 初期設定 → API接続 → SHADOW → 初回確認 → ACTIVE`。
- vertical追加はconfig / template駆動にする。
- 顧客には内部Agent、DOT、LABを見せない。

### DOT

- MAINLINE runtimeに依存しない、独立したAI教育・監査・R&D組織とする。
- 基本サイクルは `作る → 壊す → 修正 → regression → 独立監査 → 凍結`。
- Writerをbenchmarkと実KPIで継続育成する。
- 必要な補助システムはLABで構築する。
- 凍結成果物はPROMOTION WINDOWでのみMAINLINEへ昇格できる。

### PROMOTION WINDOW

次の条件をすべて満たし、HQが明示承認した場合だけ昇格する。

- MAINLINEがquiet / ready / `armed=false`
- publication、ambiguity、reconciliationがない
- rollback baselineが確定している
- current MAINLINEとの差分を再照合済み

昇格順は原則として `READ ONLY → SHADOW → LIMITED → ACTIVE` とする。
